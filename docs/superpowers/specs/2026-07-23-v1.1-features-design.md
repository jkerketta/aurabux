# v1.1 — Friend Portfolio View, Achievements, Streaks, Watchlist, Net Worth Graph

## Overview

Five new features plus three synergy additions that enhance engagement, replayability, and quality of life in Aurabux. Each feature integrates into existing user flows rather than introducing new navigation surfaces.

## Features

### 1. Friend Portfolio View (slide-up sheet)

**Trigger:** FriendsModal friend rows get a chevron button (alongside the existing ✕ remove button). Clicking the chevron opens a slide-up sheet.

**Sheet contents:**
- Friend's avatar (StockLogo placeholder) + username + display_number at top
- Donut chart (reuse `HoldingsDonut` — holdings allocation + cash slice)
- Holdings table (read-only — reuse the table layout but no `onClick`, no router navigation)
- Balance card + total portfolio value card
- Row of up to 5 unlocked achievement badges (synergy with feature 2)

**Data flow:**
- New endpoint: `GET /api/friends/[id]/portfolio`
- Validates: (a) caller is authenticated, (b) accepted friendship exists between caller and target user
- Uses `createAdminClient()` (service role) to read the friend's `holdings`, `portfolios`, and `user_achievements` — existing RLS blocks cross-user reads
- Fetches live prices + logos in parallel (same pattern as own holdings page)
- Returns: `{ username, display_number, balance, total_value, holdings[], achievements[] }`

**RLS:** No changes to existing RLS. The service role bypasses RLS, and the endpoint validates friendship before serving data.

**Files:**
- Create: `src/components/friends/friend-portfolio-sheet.tsx` (client — slide-up sheet)
- Modify: `src/components/friends/friends-modal.tsx` (add chevron button, wire up sheet)
- Create: `src/app/api/friends/[id]/portfolio/route.ts` (server endpoint)

### 3. Streaks (spin-based)

**Definition:** Current streak = number of consecutive calendar days (ending today or yesterday) where the user has ≥1 row in `daily_spins`. Streak breaks if a day is missed.

**Computation:** `src/lib/streak.ts` provides:
- `getCurrentStreak(userId)` — query daily_spins ordered by `created_at DESC`, walk dates backward, stop at first gap (comparing calendar dates, not timestamps)
- `getLongestStreak(userId)` — for the streak_100 achievement verification
- `getStreakBonus(streak)` — returns multiplier: `min(1 + streak * 0.10, 1.70)` — applied to ABX spin rewards

**No new database table** — streaks are computed from `daily_spins.created_at` on demand. Cached via the existing in-memory cache (60s TTL) to avoid repeated queries within a single page load.

**Bonus application:**
- In `POST /api/spin` handler, after determining reward type is `abx`:
  - Query current streak
  - Apply bonus multiplier to the ABX amount
  - Record the spin row in `daily_spins` (this also extends/breaks the streak)
  - Insert transaction with the bonus-adjusted amount

**UI:**
- Inside the existing SpinModal (which opens when you click "Daily Spin" on the dashboard):
  - Small "🔥 N-day streak" badge in the modal header
  - "+X% streak bonus" label below the spin button (only visible if streak > 0)
  - If streak is broken (user didn't spin yesterday), the badge shows "🔥 Streak broken — spin today to restart"

- Create: `src/lib/streak.ts`
- Modify: `src/components/spinner/spin-modal.tsx` (add streak badge + bonus label)
- Modify: `src/app/api/spin/route.ts` (apply streak bonus to ABX rewards)

### 5. Net Worth History Graph

**Database:**
- New table: `portfolio_snapshots` (migration `024_portfolio_snapshots.sql`)
  ```sql
  create table public.portfolio_snapshots (
    id uuid default gen_random_uuid() primary key,
    user_id uuid references public.users(id) on delete cascade not null,
    total_value numeric not null,
    snapshot_at date not null default current_date,
    unique (user_id, snapshot_at)
  );
  create index idx_portfolio_snapshots_user on public.portfolio_snapshots (user_id, snapshot_at desc);
  ```
- RLS: owner can read. INSERT is done via service role in the dashboard server page (not user-writable — prevents users from inflating their net worth history).

**Snapshot mechanism:**
- At the top of `src/app/dashboard/page.tsx`, after auth check, before other data fetching:
  ```ts
  const admin = createAdminClient();
  const today = new Date().toISOString().slice(0, 10); // 'YYYY-MM-DD'
  await admin.from("portfolio_snapshots").upsert({
    user_id: user.id,
    total_value: computedTotalValue, // balance + holdings value (live prices)
    snapshot_at: today,
  }, { onConflict: "user_id,snapshot_at" });
  ```
- The `unique(user_id, snapshot_at)` constraint makes this idempotent — first load of the day writes the value; subsequent loads either skip (if we add a check) or overwrite with the latest price (preferable — captures the most accurate end-of-day value).
- Only active users get snapshots (a user who never loads the dashboard that day doesn't get a row — acceptable, and avoids the need for a cron job).

**Wait — the snapshot needs the live total_value, which itself requires parallel price fetches.** The snapshot upsert must happen AFTER the price fetch logic. So it goes at the end of the existing holdings enrichment block in `page.tsx`, not at the top.

**API:**
- `GET /api/portfolio/snapshots?range=30d|90d|1y|all` (default 30d)
- Returns: `[{ date: "2026-07-01", total_value: 12345.67 }, ...]`
- Server queries `portfolio_snapshots` filtered by user and range.

**UI:**
- The "Investments" card on the dashboard (currently shows total investments + all-time return badge) becomes a clickable card (cursor pointer + hover state).
- Click → opens `NetWorthSheet` (slide-up sheet matching the FriendsModal pattern).
- **NetWorthSheet contents:**
  - Range toggle buttons at the top: 1W, 1M, 3M, 1Y, All
  - Bklit UI line chart — needs `npx shadcn@latest add @bklit/line-chart`. Data: `[{ date, total_value }]`.
  - Milestone markers: overlay dots/labels at dates where portfolio value first crossed a milestone threshold ($15K, $25K, $50K, $100K, $250K). Derived by walking the snapshot history and detecting threshold crossings — computed server-side in the snapshots API, returned as `milestones: [{ date, threshold, label }]`.
  - Summary stats below the chart: Starting value (first point in range) | Current value | Max | Min | Total return %

## Edge Cases

- **Friend deletes account:** `on delete cascade` on `holdings`, `portfolios`, `user_achievements` ensures no orphan data. Friend portfolio endpoint returns 404.
- **Achievement already unlocked:** `unique(user_id, achievement_key)` + `onConflict: "do nothing"` prevents double-inserts.
- **Snapshot on non-trading day:** Still records — captures cash balance + last-known prices. Acceptable.
- **Watchlist with 0 tickers:** Search page shows friendly empty state, not a blank grid.
- **Streak break on day 1:** A new user who spins once has a 1-day streak. If they don't spin the next day, the streak resets to 0. The streak is computed by counting consecutive prior days with spins, walking backward.
- **Many snapshots over years:** The `snapshot_at date` + unique constraint means max 365 rows/user/year. Even with 10K active users, this is ~3.65M rows/year — manageable for Postgres.
- **Friend has 0 holdings:** FriendPortfolioSheet shows "No holdings" empty state in the table section, donut chart shows only the cash slice.
- **Achievement evaluation race condition:** If two concurrent requests try to unlock the same achievement, the unique constraint prevents duplicate inserts. Use `.upsert({ onConflict: "user_id,achievement_key" })` or catch insert errors.
